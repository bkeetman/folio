# Domain documentation

Folio uses a single-context domain documentation layout.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant architecture decisions in `docs/adr/` when the directory exists.
- Proceed without warning when either source is absent; create domain documentation only when terms or decisions are actually resolved.

## Vocabulary and decisions

- Use the terms defined in `CONTEXT.md` in issues, tests, refactors, and user-facing plans.
- Surface conflicts with an existing architecture decision explicitly instead of silently overriding it.
- Store system-wide decisions under `docs/adr/` using numbered, descriptive filenames.
